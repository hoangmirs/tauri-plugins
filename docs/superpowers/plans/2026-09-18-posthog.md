# tauri-plugin-posthog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri plugin, and its npm package, that counts what players do by sending anonymous events to PostHog from a queue that survives the app closing — and the same events, in the same shape, from the plain web.

**Architecture:** Pure Rust, no native code. Pure pieces (payload building, the file-backed queue, identity, the flush loop) are tested on their own; HTTP sits behind a `Post` trait faked in tests. One background worker task owns the queue, so the commands only send it messages and no two writers race on the file. The npm package exposes the same five functions on Tauri (commands) and on the web (a `localStorage` queue and `fetch`), and never throws.

**Tech Stack:** Rust 2021, `tauri` 2.11.5, `ureq` 3 (rustls, bundled roots — no platform verifier), `uuid`, `time`, `serde_json`, TypeScript, `node --test`.

**Spec:** `docs/superpowers/specs/2026-09-18-update-gate-and-posthog-design.md`, section "2. tauri-plugin-posthog" and section "3. Both plugins".

## Global Constraints

- **Every dependency pinned exactly** at its latest version (`=x.y.z` in Cargo, no `^`/`~` in npm). `tauri` stays `=2.11.5`, `@tauri-apps/api` stays `2.11.1`, `ureq` stays `=3.4.2` with only its `rustls` feature. `rustls-platform-verifier` must not appear in the tree for any target (it panics on Android).
- **Crate and package version `0.1.0-alpha.1`**, MIT, repository `https://github.com/hoangmirs/tauri-plugins`. Crate name `tauri-plugin-posthog`, plugin name `posthog`, npm package `tauri-plugin-posthog-api`, directory `packages/plugin-posthog/`.
- **Anonymous only.** Every event carries `"$process_person_profile": false`, which a caller's properties can never override. There is no `identify`, no way to pass a `distinct_id`, and no person properties. The id is a random UUID made once per install.
- **Endpoint:** `POST {host}/batch/` with body `{ "api_key": "<key>", "batch": [ { "event", "properties": { "distinct_id", … }, "timestamp", "uuid" } ] }`. Hosts: `https://us.i.posthog.com` (US), `https://eu.i.posthog.com` (EU), or any custom host.
- **Each event gets its `uuid` (v4) and ISO-8601 UTC `timestamp` at capture time,** stored in the queue, so a resent batch repeats them and PostHog can drop the duplicate.
- **Queue limits** (ruling: the spec's numbers): above **1,000 events or 1 MB** the oldest events are dropped first. Flush when **20** are waiting or **30 seconds** pass, on launch, and best-effort on exit. At most **100 events per request**.
- **Retry:** a failed send keeps its events and waits before the next attempt: 30 s, doubling, capped at 10 minutes; any success resets it.
- **Analytics never breaks the app.** No command returns an error the app must handle; every JS function resolves and never rejects; a failure is logged at `warn` and dropped. A panic in the worker or the network stack must not take the app down (catch it the way update-gate does).
- **Opt-out** persists across launches. Opting out stops capture and deletes the queued events.
- **Properties the plugin adds** to every event: `distinct_id`, `$process_person_profile: false`, `$lib: "tauri-plugin-posthog"` (web: `"tauri-plugin-posthog-web"`), `$lib_version`, `$app_version` (Tauri: `PackageInfo`; web: from `init`), `$os` (`iOS`, `Android`, `macOS`, `Windows`, `Linux`; web: `Web`), `platform` (`ios`, `android`, `macos`, `windows`, `linux`, `web`). The JS adds `$locale` from `navigator.language` when present. A caller's property of the same name never overrides `distinct_id` or `$process_person_profile`; it does override the rest.
- **Lints:** `unsafe_code = "forbid"`, clippy `all` + `pedantic` at warn, CI `-D warnings`. **Tests pass with no network.**
- **Commit messages:** plain prose, no Conventional Commits prefix, no attribution lines, no emoji.

- [ ] **Step 1: Worker.** One task spawned in `setup` owns the `Queue`, `Backoff`, `Base` and the `Post`. Commands send it messages over a channel (`tauri::async_runtime` / tokio mpsc). It flushes when `len() >= flush_at`, on a `flush_every` tick, once at start, and on a `Flush` message; flushing runs the blocking `flush` in `spawn_blocking` and honours `Backoff` (a tick before `ready_in` does nothing). A panic in a flush is caught (`JoinError`) and treated as a failed send. Queue and identity files live in `app.path().app_data_dir()`; if it cannot be resolved or created, the plugin runs with capture as a no-op and logs once.
- [ ] **Step 2: Opt-out.** `capture` does nothing while opted out. `set_opt_out(true)` persists, clears the queue. `set_opt_out(false)` persists; capture resumes.
- [ ] **Step 3: Exit.** On `RunEvent::Exit` (plugin `on_event`), attempt one flush with a short deadline (2 s) and never block exit longer.
- [ ] **Step 4: Public surface.** `lib.rs` keeps every module private and re-exports only `Config` (and `init`). `$os`/`platform` come from `cfg!(target_os)`; `$app_version` from `PackageInfo`; `$lib_version` from `env!("CARGO_PKG_VERSION")`.
